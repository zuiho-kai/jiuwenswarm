# 删除额外机制

按评审要求，收件与执行排队回到现有 SDK。

## 已删除

- `duplex_ingress.py`：50ms DB 预取循环、额外收件锁、全局 `EventBus.start/stop` 改写和后台派发任务。
- Native 独立等待队列：安全暂停期间的新投递返回失败，由入口保留并重试；不另排一队。
- 三处 32 条容量限制，以及消息、批次、摘要和约束的固定字符/条数截断。
- 额外默认 2 秒期限及 30 秒上限，包括评测适配器中的硬编码。默认沿用模型自身请求超时；用户显式配置的 `timeout_seconds` 仍有效。
- 判断超时、异常、非法结果及过期决定自动转成 APPEND 的兜底。失败返回入口，DB 保持未读；用户入口返回错误。

## 保留及行为边界

- 判断层只暂存正在处理的输入，合并真正并发到达的消息并校验版本；实际消息投递仍走 SDK。
- DB 处理器按原顺序等待投递结果，再读后续消息。不再承诺判断期间主动抢读后续 DB 消息；事件总线也恢复原 SDK 串行派发。
- 未配置额外总期限时，由模型配置的请求超时决定单次调用等待时间。这里不新建容量或字符预算策略；大输入超出模型限制时明确失败。
- 计划来源校验、ACK 前持久化、工具和网页动作收据、安全暂停及恢复继续保留。这些用于关闭已复现的数据丢失窗口。
- 慢 Agent 已结束、没有活动轮次时，失效的旧判断交回 SDK 接收新输入；仍在执行的过期决定不应用。
